# Новая студия за 6 минут

Что нужно: фото (главное, логотип, 3–12 работ), название, адрес, телефон, график, список услуг с ценами. Проект Supabase и хостинг уже настроены (`SETUP.md`).

| Мин | Шаг | Команда / действие |
| --- | --- | --- |
| 0–1 | Создать папку студии | `pnpm tenant:new my-studio --name "Моя студия" --accent "#E5533D"` |
| 1–3 | Заполнить `tenants/my-studio/business.json`, положить фото в `tenants/my-studio/media/` | slug — латиница и дефисы; цены целыми рублями; ровно 3 информационные карточки; бокс = ресурс, который нельзя занять дважды |
| 3 | Проверить | `pnpm tenant:validate my-studio` — скажет, что не так (формат/размер фото, контраст акцента на чёрном, ссылки услуг на боксы) |
| 3–4 | Записать в базу | `DATABASE_URL=… pnpm tenant:publish my-studio` — студия появляется как **образец** |
| 4–5 | Собрать и выложить | `git add tenants/my-studio && git commit && git push` (хостинг соберёт `pnpm build`) |
| 5 | Выдать доступ владельцу | `SUPABASE_URL=… SUPABASE_SERVICE_ROLE_KEY=… pnpm owner:create my-studio` — покажет пароль один раз |
| 5–6 | Проверить и включить | `DATABASE_URL=… pnpm tenant:verify my-studio --dist dist --url https://ваш-адрес --activate` |

Результат: `https://ваш-адрес/s/my-studio/` — клиентам, `…/s/my-studio/owner/` — владельцу. У студии свои название, цвет,
иконка приложения, manifest и worker; данные других студий ей недоступны.

## Что менять потом

- **Цены, график, правила записи, фото работ** владелец меняет сам в кабинете («Настройки», «Фото»).
- **Из файла** можно заново опубликовать всё сразу — записи и фото владельца сохранятся, но поля, которыми управляет файл,
  вернутся к значениям из файла. Выбирайте один способ правки на поле.
- Услугу убрали из файла — она отключается, старые записи остаются с прежней ценой.

## Если проверка не прошла

`tenant:validate` и `tenant:verify` печатают, что именно не так (✗), и завершаются кодом 1. `--activate` без успешной проверки не включится.
