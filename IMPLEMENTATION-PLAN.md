# IMPLEMENTATION-PLAN

Собран по продуктовому промпту из доски «MVP Автосервис от SGX» (экспорт PDF) и промпту реализации.
Файла плана в доске не было, поэтому этапы, модель данных и демо-данные ниже определены здесь
и считаются источником истины для остальных документов.

## Решения, принятые вместо недостающих частей плана

| Вопрос | Решение |
| --- | --- |
| Время занятости | Услуга занимает ресурс на непрерывный wall-clock диапазон `[start, start + duration + buffer)`. Ночи и выходные внутри диапазона заняты. |
| Рабочие часы | Определяют моменты приёма (старт). Короткая услуга (≤ рабочего окна дня) обязана закончиться до закрытия; многодневная принимается в рабочее окно, дальше стоит в боксе. |
| Единственный источник доступности | SQL: `public.availability()` и `public.create_booking()`; клиент не считает слоты сам. |
| Защита от двойной записи | `resource_occupancies` + `EXCLUDE USING gist (resource_id WITH =, during WITH &&)`. Брони и блокировки пишутся в одну таблицу. |
| Ответы RPC | Бизнес-ошибки возвращаются как `{ok:false, code}` (а не исключением), чтобы счётчики лимитов не откатывались. |
| Повторная выдача доступа | Токен = `HMAC(server_secret, tenant_id:idempotency_key)`; в БД только `sha256(token)`. Повтор с тем же ключом и теми же данными отдаёт тот же токен. |
| Конфиг студии | `tenants/<slug>/business.json` + `media/`. Картинки из конфига — статика сборки, загрузки владельца — Supabase Storage. Переиздание не трогает записи и `origin='owner'` фото. |
| Bottom sheet | Один выбранный вариант: Astryx `BottomSheet`. shadcn подготовлен (`components.json`, `cn`, мост токенов Tailwind↔Astryx), shadcn Drawer/Vaul не используется. |
| AI | OpenAI SDK с `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL`; цикл инструментов с лимитом шагов + запасной режим JSON-intent. Владельческие инструменты исполняются под JWT владельца (права проверяет БД). |
| Окружение проверки | Supabase CLI/Docker недоступны. SQL-тесты идут на реальном PostgreSQL 16 с тестовым bootstrap ролей и схемы `auth`. GoTrue и PostgREST в тестах заменены минимальным harness. Это записано в `ACCEPTANCE.md`. |

## Этапы

1. **База данных**: таблицы, составные tenant-FK, RLS, GRANT, `resource_occupancies` с EXCLUDE, RPC создания/переноса/отмены, оплаты, лимиты, outbox, статистика. SQL-тесты.
2. **Конвейер студий**: `business.json` + Zod, `tenant:new / validate / publish / verify`, seed из конфигов.
3. **Клиентское приложение**: `/s/{slug}/`, главная, услуги, запись (bottom sheet), «Моя запись», AI-чат.
4. **Кабинет владельца**: `/s/{slug}/owner/`, записи, действия, оплаты, настройки, галерея, статистика, AI владельца.
5. **Edge Functions**: `assistant`, `push-dispatch`, общий код AI и лимитов (файл календаря .ics формируется в браузере, отдельной функции нет).
6. **PWA на студию**: manifest/иконки/метаданные, worker со своим scope и кэшами, очистка приватных данных при выходе.
7. **Тесты**: Vitest (слоты, AI-роутер, конфиг), SQL-интеграционные, один Playwright-сценарий.
8. **Документация и сдача**: `SETUP.md`, `CLONE-IN-6-MINUTES.md`, `ACCEPTANCE.md`, `.env.example`.
